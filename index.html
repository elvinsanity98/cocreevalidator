How to Use This Tool

// a quick guide for COCREE 2.0 submitters

▣ Validator

  1. Upload the unencrypted, decompressed .xml or .txt COCREE 2.0 file.
  2. Click Run Validation. The tool simulates Stage 1 (Structure), Stage 2 (Business Rules), and Stage 3 (Loading-phase / duplicates) checks.
  3. Each finding shows: Line/Record · Stage · Error Code · Field + the offending value.
  4. Filter findings by stage, severity, or search by field/code, then export the report.

Note: This is an offline pre-submission checker. It does not submit to BSP BRMS. Always run the official validation after.

⚒ Auto-Fix & Download SANDBOX

  1. After running validation, click Auto-Fix & Download.
  2. The tool repairs only mandatory and dependency-driven errors: missing required fields, invalid domain values, malformed dates, bad TIN format, length issues, negative amounts, duplicate IDs, broken cross-references, and recalculates Header/Footer counts.
  3. Optional/business-content fields are left untouched.
  4. Review the change log, preview the corrected file, then download as .xml or .txt.
  5. Use Re-validate to confirm the fixed file passes.

⚠ Sandbox only. Autofilled placeholder values must never be submitted as live regulatory data.

⬢ Sandbox Generator

  1. Set Provider Code, File Reference Date, Branch.
  2. Tick which record types to generate.
  3. Click Generate Sample. The tool fills all mandatory and dependency-driven fields with valid domain values.
  4. Use Send to Validator to immediately re-check the generated file.

Sandbox only. Do not submit auto-filled data as live regulatory reports.

What gets auto-fixed

  • Missing mandatory fields → filled with valid sample values
  • Invalid domain values (Gender, Currency, ContractType, etc.) → replaced with valid one
  • Bad date formats → reformatted to YYYYMMDD when salvageable
  • Invalid/short TIN → generated 12-digit numeric TIN
  • ProviderCode length ≠ 10 → padded/synced with Header
  • Negative amounts where not allowed → flipped positive
  • StartDate > PlannedEndDate → PlannedEndDate pushed +5 yrs
  • Duplicate ProviderSubjectNumber → suffix added
  • Contract pointing to missing subject → re-pointed to existing subject
  • Header/Footer record counts → recalculated

Common Stage 1 errors covered

  • 30-002 Filename format invalid
  • 30-006 Provider Code mismatch in file vs filename
  • 30-007 File Reference Date invalid / future-dated
  • 30-008 Number of records mismatch with footer
  • 30-009 Invalid Record Type
  • 30-013/014 Header / Footer missing
  • 30-015 Version or Submission Type missing/invalid
  • 30-019 Header vs Footer FileReferenceDate mismatch
  • 30-022 Provider Subject No. missing
  • 30-024 Provider Contract No. missing
  • 40-005 Filename of zip vs inner file mismatch

Common Stage 2 errors covered

  • 10-005 Date of Birth format
  • 10-022 Contract Type not in domain
  • 10-028 Original Currency invalid
  • 10-102 Contract Phase invalid
  • 10-150–155 Mandatory contract fields
  • 20-001 to 20-020 Mandatory subject fields (Gender, Names, TIN, etc.)
  • 20-040 / 20-041 / 20-042 Nationality / Resident / Civil Status
  • 20-050 TIN length 9–12 digits
  • 20-051 / 20-052 SSS / GSIS length
  • 20-200+ Negative-value checks
  • 10-251 / 10-252 Contract phase vs start/end date

Stage 3 (Loading) checks

  • 10-090 Duplicate ProviderSubjectNo across subjects
  • 20-310 Duplicate ProviderContractNo + RefDate
  • 10-307 Contract references a subject that doesn't exist in file
  • 10-309 Same subject linked twice to a contract
  • 10-318 Company Link parent or child not in file
  • 10-320 Company Link parent == child

About

Eeejay COCREE Checker is an unofficial pre-submission validator built on top of the BSP COCREE 2.0 Validation User Guide (CSP-004-v002), Appendix VUG-1, VUG-2, VUG-3.
